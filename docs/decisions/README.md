| [0017 — The flake was a security header](0017-the-flake-was-a-security-header.md)             | Issue #26, closed: the browser suite lost a different test every run because `Cross-Origin-Opener-Policy: same-origin` swaps the browsing-context group on a page's first navigation away from `about:blank`, and Firefox's Playwright driver intermittently loses that navigation — `page.goto` never returns although the document is complete and its `load` event has fired. | [0018 — The focus a link never asked for](0018-the-focus-a-link-never-asked-for.md)           | Issue #32, closed, and with it the WebKit strand ADR-0017 left open. The cause was not Playwright's `.focus()` and not Linux WebKit: the profile panel moved focus to its own heading whenever it appeared, arrival included, and on a deep link that landed an unpredictable moment after the page was readable — stealing focus from the test that had just focused a shape, and from any visitor who had started tabbing. Neither suggested fix is taken: more WebKit retries would have hidden a real site defect, and rewriting the eight `.focus()` call sites would have removed the only thing reporting it. Records that the worse half was never the flake — the heading sits below the map, so an arriving keyboard visitor was dropped past the skip link, the search, the year and the map with no way forward — that Escape no longer closes a profile the instant a deep link arrives, and that one cause found is not a suite proved clean.                                                                                                                                                                                                                                                                                  |
